# 텍본 정리기

## 목적

TXT 파일 한 개를 열어 안전한 로컬 규칙으로 정리하고, 원본과 결과 및 변경 전후를 확인하면서 결과를 직접 수정합니다.

## 현재 구현 범위

- `.txt` 파일 한 개 열기 및 드래그 앤 드롭
- UTF-8 BOM, UTF-8, UTF-16 LE/BE, EUC-KR(CP949 계열), Shift-JIS 판별
- 행 앞의 공백과 탭 제거
- 연속된 공백 정리
- 문장 중간에 들어간 개행 후보 연결
- 표, 탭 구분 행, 박스 드로잉 문자, 구분선, 코드 블록 보호
- 원본과 결과를 나란히 표시하고 스크롤 동기화
- 변경 유형, 줄 번호, 수정 전 문자열, 수정 후 문자열 탐색
- 결과 영역 직접 편집
- 원본과 결과를 CodeMirror 기반 가상화 편집기로 표시하고 실행 취소·다시 실행 지원
- 따옴표 짝 불일치·누락 의심 구간 표시 및 해당 결과 위치로 이동
- 직접 편집 후 Worker에서 따옴표 재검사, 오래된 검사 응답 폐기
- 최대 128MB 원본 처리 및 Web Worker 분석
- 원본 바이트를 `<원본명>.bak.txt`로 보존
- 결과를 원본 파일명에 UTF-8 BOM으로 저장
- 기존 `.bak.txt`가 있으면 타임스탬프 이름으로 순환 보관
- 파일을 연 뒤 외부에서 원본이 변경됐으면 저장 중단
- 같은 폴더의 임시 파일을 이용한 원자적 교체와 실패 시 복구

## 처리 원칙

- 렌더러는 파일을 직접 읽거나 쓰지 않고 Electron IPC를 사용합니다.
- 분석은 별도 Worker에서 실행해 대형 파일 처리 중 UI 점유를 줄입니다.
- 편집기는 문서 모델에 전체 텍스트를 보관하고 화면에 보이는 구간만 렌더링합니다. React state에는 전체 편집 문자열을 매 입력마다 복사하지 않습니다.
- 편집기와 관련 모듈은 텍본 정리기와 함께 지연 로딩합니다. 검색 강조와 위치 이동은 편집기 API를 사용하며 전체 본문을 복제한 숨김 DOM을 만들지 않습니다.
- 검색 이동 시 선택 영역을 먼저 반영하고 양쪽 편집기 위치를 맞춥니다. 자동 이동 뒤의 지연된 스크롤 보정은 재동기화하지 않으며, 휠·터치·스크롤바·키보드 입력 시 동기화를 재개합니다.
- 직접 입력 중에는 전체 본문을 읽지 않고, 마지막 입력으로부터 350ms 뒤에 편집 내용을 반영합니다. 한글 등 조합 입력 중에는 반영을 미루며 저장·검색 이동 시에는 최신 편집 내용을 즉시 사용합니다.
- 편집 후 줄 수·결과 검색·따옴표 검사는 Worker에서 처리하며, 새 입력이 발생하면 이전 검사 응답을 폐기합니다.
- 자동 규칙은 표나 특수문자 기반 레이아웃으로 판단한 줄을 건너뜁니다.
- 문장 중간 개행은 확실한 문장 끝, 빈 줄, 제목·목록 시작, 보호된 줄에서는 연결하지 않습니다.
- 자동 결과는 제안이며 사용자가 결과 영역에서 직접 수정한 내용이 최종 저장본입니다.
- 따옴표는 자동으로 바꾸지 않습니다. 정리 결과에서 의심 사유·줄 번호·미리보기를 제공하고 사용자가 직접 수정합니다.
- 따옴표 검토 목록은 최대 1,000건을 표시하며 전체 의심 건수와 표시 제한을 안내합니다.

## 저장 규칙

예를 들어 `novel.txt`를 저장하면 다음과 같이 처리합니다.

1. 로드 시점의 크기와 SHA-256이 현재 원본과 같은지 확인합니다.
2. 결과를 같은 폴더의 임시 파일에 UTF-8 BOM으로 쓰고 디스크 동기화를 수행합니다.
3. 기존 `novel.bak.txt`가 있으면 `novel.bak.YYYYMMDD-HHmmss.txt`로 이동합니다.
4. 기존 `novel.txt`를 `novel.bak.txt`로 이동합니다.
5. 임시 결과를 `novel.txt`로 이동합니다.
6. 실패하면 가능한 범위에서 원본과 기존 백업을 복구하고 임시 파일을 제거합니다.

## 후속 범위

- 개별 변경 적용·제외 및 사용자 정의 정규식
- 장과 회차 자동 인식
- 규칙 순서 변경과 사용자 프리셋
- 편집 후 Worker 검사에 전체 문자열 대신 변경 구간만 전달
- 문맥을 고려한 따옴표 검사의 정확도 개선
- 맞춤법 검사기 연동
- 선택된 문단만 LLM에 전달하는 교정 작업
- 교정 결과를 범위 패치로 받아 충돌을 검증하는 기능

## LLM 적용 제한

- 전체 파일을 한 번에 외부 API로 전송하지 않습니다.
- 사용자가 선택하거나 승인한 구간만 요청합니다.
- 응답은 완성된 전체 텍스트가 아니라 원문 범위, 원문, 교정문으로 구성된 패치로 받습니다.
- 원문 범위가 현재 결과와 다르면 자동 적용하지 않고 충돌로 표시합니다.
- 로컬 규칙과 LLM 처리는 별도 단계로 두어 재현성과 비용을 관리합니다.

## 알려진 제한

- 현재 문장 중간 개행 연결은 휴리스틱이므로 시, 가사, 의도적으로 문장 부호를 생략한 문단은 직접 확인해야 합니다.
- 직접 수정한 뒤 규칙을 바꾸거나 다시 분석하면 직접 수정 내용은 사라지므로 확인 대화상자를 표시합니다.
- 따옴표와 맞춤법 교정은 오탐 방지를 위해 아직 자동 적용하지 않습니다.
- 따옴표 검사는 문단 단위 규칙입니다. 빈 줄을 넘어 이어지는 인용과 특수한 아포스트로피 표기는 의심 항목으로 표시될 수 있습니다. 표와 코드 블록은 검사에서 제외합니다.
