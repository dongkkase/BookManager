# 파일 도구 구조

## 목적

`파일 도구` 탭은 기존 최상위 탭을 대체하지 않고, 현재와 향후 파일 편집 기능을 한 화면에서 찾을 수 있게 하는 도구 카탈로그입니다.

## 기본 원칙

- 기존 `폴더`, `압축 파일 구조 정리`, `내부 파일명 변경`, `메타데이터 관리`, `공유 서버`, `업데이트 및 릴리즈 노트` 탭을 유지합니다.
- 기존 기능은 파일 도구 카탈로그에서 원래 탭으로 이동하는 바로가기로 제공할 수 있습니다.
- 새 기능은 `파일 도구` 탭 안에서 지연 로딩합니다.
- 준비 중인 도구는 레지스트리 정보만 등록하고 실행 컴포넌트나 무거운 의존성을 불러오지 않습니다.
- 새 도구를 추가할 때 최상위 `App`에 도구별 조건을 추가하지 않습니다.

## 도구 상태

- `available`: 현재 사용할 수 있는 도구 또는 기존 탭 바로가기
- `next`: 다음 구현 대상으로 표시하지만 아직 실행할 수 없는 도구
- `planned`: 준비 중인 도구
- `downloadable`: 별도 도구팩을 설치하면 사용할 수 있는 도구

## 이동 대상

기존 기능 바로가기는 `target.type`을 `tab`으로 지정합니다.

```js
{
    id: 'archive-organizer',
    status: 'available',
    target: {
        type: 'tab',
        tabId: 'organizer',
    },
}
```

파일 도구 내부 기능은 구현 시 `target.type`을 `tool`로 지정하고 컴포넌트를 동적으로 불러옵니다.

```js
{
    id: 'text-cleaner',
    status: 'available',
    target: {
        type: 'tool',
        load: () => import('../../features/fileTools/textCleaner/TextCleanerTool.jsx'),
    },
}
```

## 파일 전달

파일 도구 목록 화면에서는 외부 파일과 앱 내부 파일 경로 드래그앤드롭을 차단하고 호버 안내를 표시하지 않습니다. 텍본 정리기를 연 뒤에만 드롭과 호버 안내를 활성화하며, 파일을 여는 처리는 도구의 드롭 핸들러가 담당합니다.

목적 도구가 없는 파일 전달 요청은 도구 목록에서 처리하지 않습니다. 우클릭 메뉴처럼 목적 도구를 명시한 요청은 해당 도구를 열어 파일을 전달합니다.

다른 탭에서 파일을 전달할 때는 `bookmanager:navigate` 요청에 목적 도구를 명시합니다.

```js
{
    tabId: 'tools',
    toolId: 'text-cleaner',
    paths: ['/books/a.txt'],
    mode: 'append',
    source: 'folder',
}
```

도구는 파일을 받기 전에 지원 형식을 검사하고, 거부된 파일과 이유를 사용자에게 표시해야 합니다.

## 실행 경계

- Renderer는 도구 선택, 옵션, 미리보기와 진행 상태를 담당합니다.
- 실제 파일 읽기와 쓰기, 대형 연산은 Electron 메인 프로세스의 작업 모듈이 담당합니다.
- 결과는 임시 파일에 먼저 기록하고 검증 후 최종 경로로 이동합니다.
- 기본 설정에서는 원본 파일을 덮어쓰지 않습니다.
